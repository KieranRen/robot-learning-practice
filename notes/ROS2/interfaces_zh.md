# ROS 2 接口与双臂驱动

[English](interfaces.md) | [中文](interfaces_zh.md)

## 概览

2026 年 11 月 20–21 日学习笔记。以天机双臂驱动为例，理解上层程序如何连接机器人、发送运动目标、读取实际状态。下文的驱动约定来自本次阅读的接口资料，运动示例为纸面推演。

## 1. 节点、接口名和接口类型

ROS 2 节点是一个负责处理某项工作的计算单元。一个节点可以同时提供多个接口。节点名回答「谁来处理」，接口名回答「消息或请求发到哪里」，接口类型回答「交换的数据有哪些字段」。

| 机制 | 交互方式 | 定义文件 | 常见用途 |
|---|---|---|---|
| Topic | 发布者发消息，订阅者接收 | `.msg` 定义一条消息 | 持续读取状态或更新目标 |
| Service | 客户端发一次请求，收到一次回复 | `.srv` 用 `---` 分隔 Request 和 Response | 连接、配置、选模、一次性下发命令 |
| Action | 客户端提交 Goal，执行中可收反馈、请求取消，最后取结果 | `.action` 文件依次写 Goal、Result、Feedback | 一次运动或标定任务 |

例如，`/tianji_driver` 是节点，`/tianji/feedback` 是接口名，`ArmFeedbacks` 是外层消息类型。嵌套消息类似 C 里一个 `struct` 当作另一个 `struct` 的字段。同一种消息类型也可以放进 Topic 消息、Service 请求或 Action 目标。联系 MuJoCo 中写控制输入和读 `qpos` 的区别，ROS 2 让这两类数据能在节点之间传递。

## 2. Service 请求和回复

| Service | 请求做什么 | `success=true` 确认什么 |
|---|---|---|
| `Command` | 共用连接的连接和断开不指定手臂；清错和停止要指定手臂。 | 请求已受理。收到停止回复时，机械臂可能仍在减速。 |
| `SetMotionProfile` | 按组修改速度与加速度限值比例、关节阻抗、笛卡尔阻抗或阻抗轴。速度和加速度比例成对更新。 | 反馈确认选中参数已生效，模式保持原样。任一选中值无效则拒绝整次请求。 |
| `SetMode` | 选择一条臂的控制模式，适用时再选择拖动方向。 | 新反馈确认了请求的模式和方向。 |
| `SetToolTransform` | 设置 TCP（工具中心点）相对法兰的固定位置和朝向。平移用米，四元数顺序为 `xyzw`。 | 变换已更新并保存。 |
| `set_gripper_enabled` | 用布尔值启用或停用一侧夹爪。 | 夹爪电机的新反馈确认了请求状态。停用会清除待执行目标。 |
| `SetGripperMIT` | 给已启用的夹爪发一帧命令。 | 一帧已下发。实际运动情况从反馈 Topic 读取。 |

配置运动参数时要求已连接、反馈有效、无故障且停稳。选非零模式时还要求当前没有运动控制源占用。模式 0 为下使能，1、2、3 分别是关节位置、关节阻抗和笛卡尔阻抗，4、5 是关节和笛卡尔手动拖动。模式 5 的方向编号 1/2/3/4 对应 X/Y/Z/旋转，其他模式的方向字段填 0。更换拖动类型或方向前，要松开引导按钮并等机械臂停稳。

## 3. Action 的目标、进度和完成条件

| Action | 提交什么目标 | 进度和成功的含义 |
|---|---|---|
| `MoveJointPosition` | 在模式 1 下发送单臂七轴角度目标，目标里的手臂标识与路径一致。驱动从实测起始位置插值。 | 进度来自实际关节总位移。实测关节进入目标容差并停稳后才到 1，文档的默认容差为每轴 0.1°。 |
| `MoveJointImpedance` | 在模式 2 下发送单臂七轴平衡目标，驱动从实测起始位置插值。 | 进度跟踪的是平衡目标插值。成功表示最终平衡目标已提交，受外力时实际角度仍可能有偏差。 |
| `CalibrateToolDynamics` | 指定手臂、文件基本名和采集模式。调用时运动入口已关闭且机械臂停稳，两臂分开采集。 | 执行中可看阶段和进度。采集结果指向 CSV，应用工具参数后的结果指向参数文件，此时质量、质心和惯量有效。 |

两个运动 Action 都沿用已配置的速度和加速度比例，提交前要选好对应模式。假设关节从 10° 去 40°。在位置模式下，实测到 25° 约等于走完一半位移。在阻抗模式下，平衡目标可以已经更新到 40°，而外力仍让关节实际停在 35°。Action 报告的是当前任务的进度，反馈 Topic 报告的是实测角度。

标定时，`"empty"` 表示单独采集空载数据，`"loaded"` 表示单独采集带载数据。空字符串 `""` 用于两阶段流程。第一次 Goal 得到 `BASELINE_READY`，安装工具后再发一次空字符串 Goal，完成带载辨识和写回，得到 `TOOL_APPLIED`。质量用 kg，质心位置在法兰系下以 m 表达，惯量在法兰原点及其坐标轴下以 kg·m² 表达。

## 4. Topic 和公共嵌套消息

| Topic | 上层程序怎么用 | 一帧有什么 |
|---|---|---|
| `/tianji/feedback` | 订阅 | `ArmFeedbacks` 封装两个 `ArmFeedback`，固定 A 在前、B 在后。 |
| `/tianji/target/joint_position` | 发布 | A、B 两臂的关节位置目标，以及对应夹爪命令。 |
| `/tianji/target/joint_impedance` | 发布 | A、B 两臂的关节平衡目标、可选的阻抗参数更新，以及对应夹爪命令。 |
| `/tianji/target/cartesian_impedance` | 发布 | A、B 两臂的笛卡尔阻抗目标，以及对应夹爪命令。 |
| `/tianji/control_cycle_hz` | 订阅 | 当前控制循环频率的报告，约每秒发布一次。 |

用反馈时先看对应臂的 `valid`，两臂分别判断。该臂的 `sample_time` 是最近一次有效反馈的接收时间。反馈还包括模式、使能状态、故障、参数回读、关节角与角速度、末端位姿和力、工具配置、夹爪角度和扭矩。部分状态字段用 255 表示未知或不适用。超过 1 秒没有新夹爪反馈时，夹爪角度和扭矩填 NaN。

目标消息的数组顺序可变，但每帧必须各有一个 A 臂和 B 臂目标。`gripper_targets[i]` 对应 `targets[i].arm` 指定的夹爪。两臂都要处于对应模式并可接收目标，任何一侧不满足条件就拒绝整帧。

反馈和连续目标的标称频率为 500 Hz，约每 2 ms 一帧。消息流的标称频率和单独发布的控制循环频率是两个量。驱动使用 ROS 域 66。反馈 QoS 为 Reliable / Volatile / Keep Last 10，连续目标则用相同的可靠性和持久性设置，历史深度为 1。QoS 描述消息的传输和保留规则。

`JointPositionTarget` 是单臂结构，既可以放进 Action 的 Goal，也可以作为双臂 Topic 目标数组的一个元素。`JointImpedanceTarget` 同理，内部再嵌套 `Impedance`，包含七项刚度和七项阻尼比。`GripperCommandValues` 在夹爪 Service 和目标 Topic 中共用，包含目标电机角度、角速度、位置刚度、速度阻尼、带符号的前馈扭矩。上层决定何时张开、合拢、判断接触和保持。

## 5. 阻抗、坐标系和单位

关节阻抗可以想成各关节上的虚拟弹簧和减振器，回拉作用用沿各关节转轴的扭矩表示。笛卡尔阻抗在工具末端的运动方向上设置软硬。例如拿海绵沿桌面擦拭时，可以设定沿桌面的刚度较高，垂直桌面的刚度较低。由哪些关节配合实现，取决于手臂姿势。

天机的笛卡尔阻抗目标包含七个关节角作为基准，以及六维目标力和力矩。目标力和力矩全零时使用基准平衡位置，非零时由目标力和所选轴上的刚度共同确定平衡位置。零刚度轴上的目标力或力矩必须为零。阻抗轴从本臂基座轴出发，绕 `body` 固定轴旋转，以恒等旋转保留基座轴向。关节阻抗按 J1–J7 排列，笛卡尔阻抗按 X/Y/Z/Rx/Ry/Rz/零空间排列。阻尼比为 0–1，无量纲，夹爪的 `kd` 则是有单位的速度阻尼参数。

| 数据 | 本驱动的约定 |
|---|---|
| 机械臂关节角 / 角速度 | deg / deg/s |
| 夹爪目标角 / 角速度 | rad / rad/s |
| 夹爪实测角 / 扭矩 | deg / N·m |
| 关节刚度 | N·m/deg |
| 笛卡尔平移刚度 / 转动与零空间刚度 | N/m / N·m/rad |
| TCP 位姿 / TCP 目标力和力矩 | `body` 系。位置使用 m，姿态是 `xyzw` 四元数，力和力矩使用 N 和 N·m。 |
| TCP 实测力和力矩 | 当前 TCP 系，力矩以 TCP 原点为参考。 |
| 工具变换和动力学 | 法兰系。 |

## 6. 串起整个控制流程

只做一次定点运动时，通过 Service 连接，订阅反馈 Topic 并检查有效性，按需设置参数，选模，然后提交 Action。执行期间继续读反馈 Topic 看实际位置。做连续双臂控制时，准备步骤相同，随后由上层程序不断向目标 Topic 发布两臂的目标，实际位置仍从同一反馈 Topic 读取。

每条臂同一时刻只接受一个运动控制源。已有运动 Goal 时，新的 Goal 会被拒绝。文档规定，连续 Topic 和 Action 交接时先请求停止、确认停稳，再重新选模。停止发布后，Topic 仍保留运动控制权。读到 Service 回复、Action 结果和实测关节角时，分别问自己「这次请求确认了什么」「这次任务怎样算完成」「机器人现在实际在哪」。
